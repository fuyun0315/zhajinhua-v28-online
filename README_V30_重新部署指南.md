# 炸金花 V30 联网对战版

## 本版主要改动
- 首页仅保留登录/注册，不再把旧版标题、房间控件和牌桌一起显示。
- 登录成功后进入独立的牌桌大厅：创建房间、单人练习、输入房间号、查看开放牌桌。
- 只有创建/加入房间后才进入牌桌。
- 修复 V29 前端初始化顺序错误：旧版在 `$` 函数定义前就调用它，导致 JavaScript 报 `Cannot access '$' before initialization`，登录/注册按钮事件根本没有绑定。
- 保留 V28 风格的绿色椭圆牌桌、底池、筹码视觉、看牌、下注、弃牌、比牌、托管、机器人、牌局日志和提示音/中文语音。
- 每桌最多 6 人，全部使用虚拟筹码，不接入真钱。
- 加入 `/health` 健康检查，版本为 V30。

## Railway 部署
1. 将本文件夹中的**所有内容**上传到 GitHub 仓库根目录，确保 `package.json` 和 `server.js` 直接位于仓库根目录。
2. Railway 连接这个仓库并重新部署（Redeploy）。
3. 构建命令可留空或使用 `npm install`；启动命令为 `npm start`。
4. Railway 为服务生成公开域名后访问根网址。
5. 可访问 `https://你的域名/health`，应返回包含 `"version":"V30"` 和 `"ok":true` 的 JSON。

## 账号保存
默认账号文件路径为 `data/accounts.json`。Railway 重新部署/重建容器后本地文件可能不保留。需要长期保存账号时，在 Railway 为服务挂载 Volume 到 `/data`，并设置变量 `ACCOUNTS_FILE=/data/accounts.json`。设置变量前请确认 Volume 的挂载路径就是 `/data`。

## 验收测试（必须实际进行）
- 用从未注册过的用户名注册，确认跳转到大厅。
- 退出后用同一账号登录。
- 输错密码应显示错误提示，不应卡住。
- 创建房间后进入牌桌，复制6位房间号。
- 另一台手机用另一账号登录并加入房间。
- 测试准备、看牌、下注、弃牌、比牌、托管、机器人、再来一局和声音。

注意：代码语法检查不等于完整端到端验收。发布后务必按上面步骤用两台设备实际测试；本版本仍是开发测试项目，未进行生产级安全审计，不要用于真钱赌博。
