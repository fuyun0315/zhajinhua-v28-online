# 炸金花 V28 网络对战版（虚拟筹码）

本项目以 V28 加强版为参照，保留牌桌主题、筹码动画、下注/看牌/弃牌/比牌、托管按钮和语音/提示音，并增加基础账号注册登录、房间号、房间大厅、机器人补位。

## 功能状态
- 注册/登录：服务器端使用 Node.js `crypto.scrypt` 对密码加盐哈希；账号信息写入 `accounts.json`。
- 真人房间：创建房间后分享6位房间号，其他玩家登录后加入。
- 机器人：房间创建者可点击“添加机器人”，凑齐两席后开始；机器人自动操作。
- 牌局：服务器负责发牌、轮次、下注、弃牌、比牌和结算；每名真人只能看到自己的底牌，牌局结束后公开。
- 筹码全部为虚拟筹码，仅供娱乐；不接入真钱、充值或提现。

这是可部署的开发版本，不代表已完成生产级安全审计或所有浏览器上的完整回归测试。机器人策略为基础随机策略；当前每桌最多两席（真人+真人或真人+机器人），房间大厅可创建多桌。

## GitHub + Railway 部署（手机也可操作）
1. 解压本 ZIP，将里面 `ZhaJinHua_V28_Remote` 文件夹中的全部内容上传到一个新的 GitHub 仓库根目录。
2. Railway 新建 Project → Deploy from GitHub Repo，选择该仓库。
3. Build Command：`npm install`；Start Command：`npm start`；Root Directory 留空（前提是 `package.json` 位于仓库根目录）。
4. 部署成功后，在服务 Settings → Networking → Public Networking 生成公网域名。
5. 两台手机打开同一个网址，分别注册/登录；一人创建房间，另一人输入6位房间号加入。若单人测试，创建房间后点“添加机器人”。

## 账号持久化提醒
Railway 容器文件系统可能在重新部署后重置。若要长期保留账号，建议为服务添加 Volume，并设置变量 `ACCOUNTS_FILE=/data/accounts.json`，挂载路径为 `/data`。未配置持久化卷时，不要把当前 JSON 文件存储当成可靠的长期数据库。

## 测试清单
- 注册、重复用户名、错误密码、刷新后重新登录。
- 两个独立浏览器/手机加入同一房间，确认操作和底池同步。
- 真人+机器人开局，轮到机器人时自动行动。
- 断线重连、连续多局、托管开关、筹码不足、所有牌型和边界情况。

## 安全说明
目前是原型/测试项目。正式公开给陌生用户使用前，建议增加请求速率限制、会话过期与持久化、房间超时清理、CSRF/来源校验、日志与监控，并对游戏状态和所有结算路径做安全测试。请勿用于真钱赌博。
