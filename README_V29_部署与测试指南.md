# 炸金花 V29 联网对战版（虚拟筹码）

## 本版本目标
- 保留 V28 单机版的绿色牌桌、座位卡片、筹码区、操作按钮、日志与音效风格。
- 增加注册/登录、六位房间号、房间大厅、真人联网对战、机器人补位。
- 每桌最多 6 名玩家；至少 2 名玩家可开局。
- 服务器负责发牌、玩家行动顺序、牌型比较与底池结算；客户端只显示本人的底牌，结束后公开。
- 虚拟筹码，仅供娱乐，不包含充值、提现或真钱下注。

## Railway 部署（手机也可操作）
1. 解压 ZIP，把 `package.json`、`server.js`、`public` 和 `v28_reference` 目录下的内容上传到 GitHub 仓库根目录。
2. 在 Railway 新建 Project，选择从 GitHub 仓库部署。
3. Build Command 填 `npm install`，Start Command 填 `npm start`；`package.json` 必须在仓库根目录。
4. 在服务 Settings → Networking 生成 Public Domain。
5. 打开网址注册两个以上账号：一个创建房间，其他账号输入六位房间号加入；单人测试可点击“添加机器人”。
6. 可访问 `/health` 检查服务是否在线，正常时返回包含 `ok:true` 和 `version:"V29"` 的 JSON。

## 账号持久化
默认账号文件为运行目录下的 `accounts.json`。Railway 重新部署可能重置容器文件，请添加 Volume（例如挂载到 `/data`），并设置变量 `ACCOUNTS_FILE=/data/accounts.json`。没有持久化卷时，不要把账号文件视为可靠长期存储。

## 已知限制（请在公开运营前处理）
- 当前为可部署测试版，不等于生产级完成品；尚未完成外部安全审计和全浏览器回归测试。
- 房间/牌局状态保存在内存中，服务重启会丢失；账号持久化与游戏状态持久化是两回事。
- 断线后的自动回座恢复、登录限速、会话管理、数据库、反作弊、监控和自动化测试仍需进一步加强。
- 每桌最多 6 人；机器人使用基础策略，不是高级 AI。
- 游戏仅使用虚拟筹码，请勿用于真钱赌博。

## 测试清单
1. 注册、重复用户名、错误密码、刷新后登录。
2. 两台不同手机打开同一个网址并加入同一房间。
3. 三至六名玩家同桌，确认所有客户端的底池、行动顺序与结算一致。
4. 单人添加机器人，机器人轮到时自动行动。
5. 看牌、跟注/加注、弃牌、比牌、托管开启/取消、重开和连续多局。
6. 检查 `/health`，以及 Railway 重新部署后的账号文件持久化情况。
