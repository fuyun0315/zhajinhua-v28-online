# 炸金花 V32 联网对战版

本版以用户上传的 `v28_reference.html` 为规则依据，重新整理为多人联网项目。游戏只使用虚拟筹码，仅供娱乐，不支持真钱下注或提现。

## 项目文件

- `server.js`：登录注册 API、持久化账号/积分、Socket.IO 实时房间、游戏规则、托管、机器人、在线人数和峰值记录。
- `public/index.html`：登录/注册首页、大厅、牌桌 UI。
- `public/client.js`：界面交互、声音/语音、发牌效果、断线刷新恢复。
- `v28_reference.html`：用户提供的原始 V28 逻辑参考文件，原样保留。

## 本版落实的规则/功能

- 每位玩家初始 1000 虚拟筹码，每局底注 20。
- 牌型：豹子 > 顺金 > 金花 > 顺子 > 对子 > 散牌；A-2-3 按特殊低顺子处理。
- 跟注自动支付当前要求金额；加注可在当前跟注额基础上额外增加20、40或自定义整数。
- 筹码不足当前跟注额时按原规则全押；筹码不足最低底注的玩家不会在结算瞬间被踢出，而是在下一局开始资格检查时退出并释放座位。新账号加入或创建牌桌时，筹码低于最低底注20会被拒绝。
- 看牌、弃牌、比牌、托管/取消托管、20 秒行动倒计时、超时自动弃牌。
- 主池/边池按每位玩家累计投入层级结算；未匹配的超额投入退还原玩家；弃牌筹码保留；每层只由有资格的玩家争夺，若整层贡献者全部弃牌则作为死钱由仍在场玩家争夺；平局余数按固定座位顺序分配。服务器先完成结算、检查筹码守恒并持久化，再播放筹码动画。
- 比牌平手遵循上传文件的实际分支逻辑：被选择的对手出局。
- 每桌最多 6 人；房间中至少 2 人；只有所有在桌玩家都准备后才发牌；等待中或已结束的房间连续10分钟无活动自动删除；正在进行的牌局不会仅因该空闲计时器而被删除。
- 开局底牌为暗牌；看牌者只能看到自己的牌；比牌过程中只有比牌双方能看到双方底牌，其他玩家仍看到暗牌；牌局结束后按原规则摊牌。
- 登录使用 HttpOnly 持久 Cookie（30 天）；刷新页面会尝试恢复登录和原牌桌。
- 当前在线账号数和历史在线峰值显示在大厅/牌桌；峰值保存在数据文件中。
- 注册账号的筹码、胜场、局数和历史峰值写入 JSON 数据文件。

## Railway 部署

1. 将本目录中的项目文件上传到 GitHub 仓库根目录。确保 `package.json`、`server.js`、`public/` 直接位于仓库根目录。
2. Railway 从该 GitHub 仓库部署，启动命令使用 `npm start`（默认即可）。
3. 在 Railway 服务的 Variables 中添加：
   - `SESSION_SECRET`：设置一个足够长、随机的秘密字符串；不要公开或复用示例值。
   - 新开游戏数据文件时设置 `DATA_FILE=/data/game-data.json`。
   - 如果要沿用旧版挂载卷中现有的 `/data/accounts.json` 账号文件，可设置 `DATA_FILE=/data/accounts.json`；本版会尝试识别 V29/V30 的旧账号格式并迁移。旧文件必须确实存在于同一个持久化 Volume 中，否则无法恢复旧账号。
4. 在 Railway 服务中添加 Volume，并将 Mount Path 设置为 `/data`。否则，账号、筹码和在线峰值文件可能在重新部署后丢失。
5. 生成 Public Domain，使用 HTTPS 访问游戏。

## 诚实说明

本补丁已通过 JavaScript 语法检查，并通过结算模块的6组定向测试及250组随机筹码守恒测试；当前执行环境未安装 Express/Socket.IO 依赖，因此没有在此环境完成服务器启动测试，也未完成 Railway 实际部署、真实双手机全流程、浏览器音频权限和生产级安全审计。上线前必须按上面的测试清单验收。默认 `SESSION_SECRET` 只是开发占位值，正式部署必须自行设置。JSON 文件适合小规模测试；如果多人长期使用，建议改用数据库和更完善的会话/断线恢复方案。


## V32 筹码结算优化补丁（本次版本）
1. 将筹码结算拆分为独立模块 `lib/settlement.js`，按累计投入分层计算主池和边池。
2. 单独处理未匹配投入并退还原玩家；弃牌玩家不能赢取奖池，但其已投入筹码仍参与奖池构成。
3. 每层仅由符合资格的在场玩家争夺；所有该层贡献者均弃牌时，将该层标记为死钱并由剩余在场玩家争夺，避免筹码丢失。
4. 平局余数按固定座位顺序分配；所有结算金额与累计投入账本核对，并记录筹码总量守恒检查。
5. 玩家筹码低于最低底注时，不会在刚结算完就立即退出；在下一局准备/开局资格检查时退出并释放座位。其他合格玩家不再被低筹码玩家卡住。
6. 新玩家筹码不足20时不能创建或加入房间。正在进行的牌局不会被10分钟空闲清理计时器直接删除。
7. 原有 V28 牌型、下注按钮、登录注册、声音、托管、机器人、底牌权限和页面布局保持不变。
