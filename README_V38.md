# 炸金花 V38 联网对战版（下注规则修正版）

本版本在现有 V37 联网对战项目基础上，补齐并统一暗牌/明牌下注计算。保留原项目的多人房间、真人与机器人、登录注册、虚拟筹码、托管、倒计时、看牌/弃牌/比牌、发牌效果、235 压豹子、底池结算等功能；此版本仍需在目标部署环境进行双设备实测后才能视为线上验收完成。

## V38 下注规则

- 首位下注者没有上家下注金额，仍可选择下注 20、40、60。
- 之后每次跟注/加注，都以当前轮次对应的**暗牌下注基准**为依据，不读取当前玩家本局累计投入。暗牌玩家的下注会更新该基准；明牌玩家的两倍支付不会抬高后续暗牌玩家的基准。
- 暗牌跟注：当前暗牌下注基准。
- 暗牌加注：当前暗牌下注基准 + 选择的加注额（20/40/60）。
- 明牌跟注：当前暗牌下注基准 × 2。
- 明牌加注：当前暗牌下注基准 × 2 + 选择的加注额（20/40/60）。加注额本身不再乘 2。
- 按钮仅显示“跟注”“加注20”“加注40”“加注60”，不附加括号金额；明牌下注使用独立的暗牌下注基准。
- 明牌比牌按该玩家正常跟注应支付的金额扣款，不使用本局累计投入计算差额。
- 机器人弃牌后重新检查仍在场玩家；牌桌中央操作按钮移至牌桌外，避免遮挡头像。
- 真人、机器人、托管共用同一套规则。当前玩家本局累计投入只用于记账、底池与结算。
- 筹码不足时允许用剩余筹码全下；不允许负筹码。

## 运行和测试

在项目根目录执行：

```bash
npm install
npm run check
npm test
npm start
```

健康检查地址 `/health` 会返回版本 `V38`。自动化测试不能代替 Railway 上使用两个独立账号/设备进行的真实多人验收。

## Railway 持久化

账号、积分和历史峰值通过 `DATA_FILE` 写入 JSON 文件。若要跨重新部署尽可能保留数据，给服务挂载 Volume（例如 `/data`），并设置 `DATA_FILE=/data/game-data.json`，同时设置独立的 `SESSION_SECRET`。Volume 挂载路径必须与 `DATA_FILE` 路径一致。
